# Deprecated error codes

**Description:** Error numbers kept for historic reference that are not in BR 5's error table.

These error numbers have pages in older BR documentation but are **not in BR 5's error table**
(`wberrdefs.h`), and no other definition of them was found in the BR 5 source. They are kept here for
historic reference only: they are not in the error-code list or its indexes, and BR no longer supports them. Where the source says more, it is
noted below.

- **311 to 368.** The BR 5 source notes that "the BR VB interface was given a range of errors that
  started around 311 and extended to about 370". Of that range only 310, 315, 317, 320 and 322 to 334 are
  defined now, and they have their own pages.
- **1101** appears in the source only as the lower bound of a range test, not as an error definition.
- **4001 to 4015, 4200 to 4361 and similar ranges** are not here: BR builds those numbers from
  operating-system error numbers, so they are not listed in the table either.

<a id="e0001"></a>
## 0001

**Description:** Inquiry key pressed

**Details:** - Pressing a function key while the program was executing (rather than waiting for input) caused the system to respond to a previous `ON ATTN` SYSTEM (for F10 key) or `ON FNKEY` ## SYSTEM statement.
- Wrong object name in a DLL call # Enter `GO` to continue. Later, you may want to modify the program so that the default of ON FNKEY ## IGNORE is reinstated for all ON FNKEY statements
- Correct the name, spelling or error-causing string or program statement

## 10054

`Client Server` connection is broken.

## Problem

Receive a `messagebox` with a title of **Error** and a body stating **Client-Server error 10054 receiving data.**

## Resolution

Check the BRConfig.log (You must turn logging on).
Review the "Launch Line" (Something like this).
   Security process has started with command c:\...\BRServer.exe -c:\...\WBConfig.sys, startdir c:\...\, logfile c:\...\brconfig.log, loglevel 10, stderr file NULL, socket handle 120, anonymous NULL
   There will most likely be another line after it explaining the reason for the problem.

- See also Error `10038`
  - Remember that while Port 8555 is typically used to initiate the inbound connection to BRListener, Ports 1024-65535 will be used to connect by to BRClient.

- Most Windows Sockets 2 functions do not return the specific cause of an error when the function returns. For information, see the Handling Winsock Errors topic.
  - http://msdn.microsoft.com/en-us/library/windows/desktop/ms740668%28v=vs.85%29.aspx

- Perhaps this is caused by a bad path in `BRListener.conf`

- Mapped Network drives WILL NOT work as the BRServer session does not have mappings.

- UNC names will work properly, but significantly affect performance.

## Troubleshooting Tips

Host:  Make sure the server name is correct, in particular, you may have moved to a new server or IP address

Label: This is case sensitive, and remember "Spaces" and perhaps other special characters require "" (Quotes)
