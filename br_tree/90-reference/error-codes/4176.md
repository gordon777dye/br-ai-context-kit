**Error:** 4176

**Description:** Another session's debug channel is waiting for its debugger; a debug channel can open once that one is attached or closes

**Details:** Raised by `DEBUG LISTEN` and `DEBUG CONNECT` when another BR session under the same Windows account has a debug channel waiting for its debugger. Every session in an account publishes its debug token to the one file `%LOCALAPPDATA%\ADS\brdebug.token`, and BR locks that file from the moment it writes it until a debugger attaches. While it is locked, no other session can write over it, so the waiting channel stays reachable and the second session is told why it cannot open.

The other session's token is untouched. Give the command again once that channel has a debugger attached or has closed: either way its file, and the lock, are gone. Only `DEBUG AUTH COOKIE`, the default, publishes a token file; with `DEBUG AUTH TOKEN` or `OFF` nothing is written, and this error does not arise.

The assistant channel's counterpart is [4173](4173.md).

**Name:** `BREDEBUGTOKENBUSY`

**Raised by:** `debug.cpp`
