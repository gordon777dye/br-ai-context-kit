**Error:** 4173

**Description:** Another session's assistant channel is waiting for its assistant; a channel can open once that one is claimed or closes

**Details:** Raised by [`MSG("harness", port)`](../../70-commands/information/MSG.md) when another BR session under the same Windows account has opened an assistant channel that nothing has connected to yet. Every session in an account publishes its channel's token to the one file `%LOCALAPPDATA%\ADS\harness.token`, and BR locks that file from the moment it writes it until an assistant claims the channel. While it is locked, no other session can write over it, so the waiting channel stays reachable and the second session is told why it cannot open.

The other session's token is untouched. Try again once that channel has been claimed or has closed: either way its file, and the lock, are gone. A program that starts sessions which open channels of their own, with [`SPAWN_RESTRICTED`](../../10-language/data-manipulation/system-functions/SPAWN_RESTRICTED.md) or otherwise, should have its own channel claimed first, or handle 4173 in the child.

The debugger channel's counterpart is [4176](4176.md).

**Name:** `BREHARNESSTOKENBUSY`

**Raised by:** `harness.cpp`
